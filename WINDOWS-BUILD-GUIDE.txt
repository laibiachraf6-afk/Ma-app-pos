# Parfum POS — بناء نسخة Windows EXE من الهاتف

هذه الملفات تضيف تغليف Electron ومهمة GitHub Actions إلى ملفات تطبيق الويب الحالية. لا تستبدل `index.html` الأصلي.

## ما الذي تفعله؟
- تفتح `index.html` داخل نافذة Windows مستقلة عبر Electron.
- تحفظ بيانات المتصفح محليًا على جهاز المستخدم باستخدام التخزين الذي تستعمله الواجهة أصلًا (مثل localStorage/IndexedDB).
- تبني ملف تثبيت Windows x64 باسم `ParfumPOS-Setup-1.0.0.exe` على خوادم GitHub Actions.

## طريقة الاستخدام من الهاتف
1. فك ضغط هذا الأرشيف على الهاتف.
2. ارفع الملفات والمجلدات إلى جذر مستودع GitHub `platform-parfum-pos`، مع الحفاظ على البنية:
   - `index.html`, `sw.js`, `manifest.json`, `icon.svg`, `Code.gs`, `package.json`
   - مجلد `electron` وفيه `main.cjs`
   - مجلد `.github/workflows` وفيه `build-windows.yml`
3. اضغط Commit changes.
4. في المستودع افتح تبويب **Actions**.
5. افتح مهمة **Build Windows Installer** وانتظر انتهاء التشغيل بعلامة نجاح خضراء.
6. افتح التشغيل الناجح، ثم في قسم **Artifacts** نزّل `ParfumPOS-Windows-Installer`.
7. فك ضغط ملف Artifact الذي تم تنزيله؛ ستجد داخله ملف `.exe`.

## ملاحظات مهمة
- هذه حزمة أولية للبناء والاختبار، وليست ضمانًا بأن كل وظائف البرنامج تعمل دون إنترنت.
- الوظائف المحلية قد تعمل دون اتصال، لكن مزامنة Google Sheets واسترجاع الحساب والبريد وأي موارد خارجية تحتاج الإنترنت.
- Service Worker لا يعمل بالطريقة نفسها داخل `file://` أو داخل Electron. التطبيق المكتبي يحمّل الواجهة محليًا، لكن يجب اختبار التخزين المحلي والطباعة والباركود على Windows.
- إذا كانت الواجهة تعتمد على خطوط Google، فستحتاج إلى اتصال لتحميلها أول مرة؛ ضع خطوطًا محلية إذا أردت استقلالًا كاملًا.
- `Code.gs` ليس خادمًا محليًا؛ هو سكربت Google Apps Script للمزامنة عند تهيئته ونشره.
- لا تضع مفتاح SECRET حقيقيًا في مستودع عام. الملف الحالي يحتوي نصًا افتراضيًا، ويجب إنشاء مفتاح قوي جديد عند إعداد المزامنة.
- لا تبيع النسخة قبل اختبار الفواتير، الجرد، النسخ الاحتياطي، صلاحيات المستخدمين، وعزل بيانات كل محل.
